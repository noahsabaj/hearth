# H0007

A runtime warning.

Two or more system parameters of different types are trying to mutably access the same component data from the same system.

To uphold the [Rust rules on references](https://doc.rust-lang.org/book/ch04-02-references-and-borrowing.html#the-rules-of-references) (either one mutable reference or any number of immutable references) for a component, queries must guarantee that it is impossible to mutably access the same component more than once within the same system.

## Error-Producing Code Example

```rust,should_panic
use hearth::prelude::*;
use hearth::platform::collections::HashMap;
use hearth::ecs::prelude::EntityMut;

#[derive(Component)]
struct Player;

#[derive(Resource, Default)]
struct Scoreboard {
    player_scores: HashMap<Entity, i32>
}

fn add_points_and_scores(
    mut players: Query<EntityMut, With<Player>>,
    mut scoreboard: ResMut<Scoreboard>
) {
    //...
}

fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        .init_resource::<Scoreboard>()
        .add_systems(Update, add_points_and_scores)
        .run();
}
```

The above code will panic at startup.
The `ResMut` system parameter mutably accesses data from a `Resource` type, which is a component that will only have one instance of itself in a `World` at any given time.
Using a `Query` parameter with `EntityMut` will provide mutable access to every `Entity`'s component data in the `World`, and will overlap and conflict with the `ResMut` parameter.

Other examples:

- Accessing `MessageWriter<M>` and `ResMut<Messages<M>>` parameters in the same system.

## Possible Solutions

- Use the `Without<IsResource>` query filter to exclude resources from the query.

```rust,no_run
use hearth::prelude::*;
use hearth::platform::collections::HashMap;
use hearth::ecs::prelude::EntityMut;
use hearth::ecs::resource::IsResource;

#[derive(Component)]
struct Player;

#[derive(Resource, Default)]
struct Scoreboard {
    player_scores: HashMap<Entity, i32>
}

fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        .init_resource::<Scoreboard>()
        .add_systems(Update, add_points_and_scores)
        .run();
}

fn add_points_and_scores(
    mut players: Query<EntityMut, (With<Player>, Without<IsResource>)>,
    mut scoreboard: ResMut<Scoreboard>
) {
    //...
}
```

- Merge the conflicting parameters into a `ParamSet`.
  - This provides disjointed access for each value in the `ParamSet`, allowing safe access for each `SystemParam`.

```rust,no_run
use hearth::prelude::*;
use hearth::platform::collections::HashMap;
use hearth::ecs::prelude::{EntityMut, ParamSet};

#[derive(Component)]
struct Player;

#[derive(Resource, Default)]
struct Scoreboard {
    player_scores: HashMap<Entity, i32>
}

fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        .init_resource::<Scoreboard>()
        .add_systems(Update, add_points_and_scores)
        .run();
}

fn add_points_and_scores(
    mut param_set: ParamSet<(
        Query<EntityMut, With<Player>>,
        ResMut<Scoreboard>
    )>
) {
    for mut entity in param_set.p0() {
        // Mutably access `Entity` component data.
    }
    // Ensure you are done using the `Query` data before you access the `ResMut`.
    for mut score in &mut param_set.p1().player_scores {
        // Mutably access the `ResMut` data next:
    }
}
```
